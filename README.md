# Forex: Telegram-бот EUR/USD, GBP/USD и USD/JPY

Лицензия проекта — GNU General Public License v3.0 (`GPL-3.0-only`).
Полный текст находится в [LICENSE](LICENSE).

Rust-бот рассчитывает сигналы по рабочему JSON, отслеживает
вход/стоп/цель и принимает уточнения правил текстом и скриншотами в Telegram.
Реальные ордера брокеру не отправляются. Бот работает только на сервере;
локальный `forex-backtest` использует ту же библиотеку стратегии и формирует PDF.

В репозитории находятся исходники, тесты, инструкции и примеры конфигурации.
Архивы котировок, базы данных, производные отчёты, готовые бинарники и локальный
комплект поставки не включены. Данные подготавливаются отдельно по инструкциям
ниже; сборка выполняется в Docker.

## Источники правил

1. Локальный `strategy/fvg-bot-rules.json` — основной источник торговых правил,
   включая гэпы, обрабатываемые как FVG без трёхсвечной формации.
2. [Требования](docs/bot-plan/requirements.md), [архитектура](docs/bot-plan/architecture.md)
   и [план разработки](docs/bot-plan/development-plan.md) — поведение и порядок работ.

Рабочий JSON един для расчётов. Серверная копия после Telegram-правок может
отличаться от локальной: для проверки серверных правил передайте их копию явно.

## Контракт и общая библиотека

Для публикации подготовлен [example.json](example.json) — пример стратегии на
основе текущего рабочего JSON, без ключей и настроек аккаунтов. При изменении
рабочих правил обновляйте пример вместе с ними. Пример не загружается автоматически. Команда его проверки приведена ниже,
после подготовки Docker-окружения.

Рабочий JSON исключён из Git. После клонирования, перед сборкой тестов,
запуском тестов или приложения, создайте его из примера:

```sh
mkdir -p strategy
cp -n example.json strategy/fvg-bot-rules.json
```

Тесты читают `strategy/fvg-bot-rules.json`. Команда копирования выполняется
один раз; `cp -n` сохраняет уже существующие рабочие правила.

Настройки Telegram/OpenAI задаются отдельно по [.env.example](.env.example).

`forex-core` содержит загрузку JSON, календарь, агрегатор и движок. `forex-bot`
содержит серверные подключения и SQLite. `forex-backtest` читает архивы и записывает
результат. Команды `check-config` и `describe-config` проверяют контракт и карту правил.

По умолчанию путь — `strategy/fvg-bot-rules.json` относительно рабочего каталога.
Проверка ничего не записывает и не обращается к Telegram, котировкам или OpenAI.
Ошибка чтения не вызывает подстановку example.json или встроенной стратегии.
Успех означает проверку контракта, а не проверку живых подключений.

Команды из корня проекта (локальная установка Rust не нужна):

```sh
docker compose build rust
docker compose run --rm rust cargo fetch --locked
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- check-config example.json
docker compose run --rm rust cargo test --workspace --locked --offline
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- check-config
docker compose run --rm rust cargo run -p forex-bot --locked --offline -- describe-config
docker compose run --rm rust cargo build -p forex-bot --locked --release
```

Единый `Dockerfile` содержит цели `dev` (разработка), `release` (экспорт
серверного бинарника) и `backtest` (расчёты и PDF). Compose выбирает
соответствующую цель; серверная сборка использует `--target release`.

Rust 1.85.1 и базовый образ закреплены версией и digest в Dockerfile,
зависимости — в Cargo.lock. При первом запуске Cargo требуется сеть для загрузки
зависимостей: запустите `docker compose run --rm rust cargo fetch --locked`.
После этого тесты выполняются без сети; ключи внешних сервисов не нужны. Сборка на
архитектуре разработчика ещё не подтверждает совместимость с целевым сервером.
Реализованы SQLite, движок, HTTP-адаптеры Telegram/OpenAI, SignalR-поток и
координатор демона с восстановлением состояния. Автором комментария считается
любой участник настроенной группы; отдельного списка ID и ручного флага
разрешения данных нет. Датированные результаты проверок находятся в
[плане разработки](docs/bot-plan/development-plan.md).

## Формат стратегии v2

`schema_version: 2` обязателен. Старый формат не читается; конвертера нет.
Рабочие числа находятся в `parameters.<имя>.value`, политики — в `policies`,
тексты недельных уведомлений — в `messages`. `comment` разрешён у объектов:
это пояснение, а не исполняемое условие. Числа из текста не извлекаются.

Telegram-правки могут менять действующие скалярные параметры и `comment`.
OpenAI получает пояснения и каталог разрешённых путей. Правка одного пояснения
не пересчитывает планы. Изменение параметра пересчитывает ожидания, сохраняя
уровни опубликованных лимиток и сделок. `describe-config` показывает ограничения,
доступные значения и доступность правки каждого параметра через Telegram.

Перед обновлением существующей установки остановите прежний демон и перенесите
в новый формат именно её рабочие значения. Пример не заменяет серверные правки.
Первый запуск v2 или `prepare-state` обновляет формат хешей старого снимка и один
раз пересчитывает ожидающие планы. Незавершённую старую операцию записи необходимо
завершить прежней версией; новая версия остановится с диагностикой.

## Исторические данные и хранилище

Данные не входят в репозиторий. Пользователь самостоятельно выбирает поставщика,
инструменты и период, получает котировки и подготавливает их для приложения.
Рекомендованных поставщиков и готовых наборов проект не задаёт.

Текущий бэктест ожидает определённый формат: ZIP с парными тиками Bid/Ask,
подготовленные минутные CSV, `manifest.json` и `quality-report.json`.
Произвольный CSV или архив другого формата напрямую не поддерживается:
потребуется преобразование, совместимое с загрузчиком
[описанием формата](docs/history-data.md). Наличие Bid/Ask само по себе
не гарантирует совместимость. SQLite-база бота не заменяет тиковые архивы.

При подготовке сохраняйте происхождение, часовой пояс, единицы цены и сведения
о пропусках. Неоднозначные котировки нельзя исправлять предположениями;
пропуски не следует заполнять вымышленными значениями. Импорт истории в базу
не запускает исторические сделки. Покрытие и стык истории с текущим потоком
необходимо проверять отдельно.

## Локальный бэктест и PDF

Первый раз собрать образ (требует сети для зависимостей):

```sh
docker compose build backtest
```

Перед запуском подготовьте данные для выбранных пар и периода. Согласуйте
каталоги в [backtest/data-sources.json](backtest/data-sources.json) и mounts
в [compose.yaml](compose.yaml). Пример ниже использует октябрь 2026; он
не подразумевает наличия этого набора после клонирования.

Запуск без сети, ключей и серверной БД:

```sh
docker compose run --rm backtest \
  --strategy strategy/fvg-bot-rules.json \
  --from 2026-10-01 --to 2026-11-01 \
  --symbols EURUSD,GBPUSD,USDJPY \
  --output reports/backtests/october-2026
```

Начало включительно, конец исключительно, время UTC. Без `--symbols` берутся все
пары JSON. Входы до начала периода не создаются. `minimum_bars` обязателен;
недобор относительно `bars_analyzed` указан в отчёте. Источники задаются в
[backtest/data-sources.json](backtest/data-sources.json); пути относительно каталога
запуска (`/app` в контейнере). Для других путей обновите read-only mounts compose.
По умолчанию пользовательские наборы размещаются в `data/history/<SYMBOL>`;
при других путях измените Compose и JSON-конфигурацию. Рабочие БД и `.env` не монтируются. Пользовательские JSON можно разместить в `strategy/`.

Каталог результата должен быть новым. В нём `report.pdf`, `results.json`,
`strategy.json`, `events.jsonl` и `trades.csv`. JSON содержит данные примеров и хеши
входных файлов/программы. `--no-pdf` выполняет только расчёт. Пересобрать PDF:

```sh
docker compose run --rm backtest --report-only reports/backtests/october-2026
```

Результат в R, только Bid/Ask-спред. Стоп исполняется по наблюдаемой котировке,
лимит и тейк по уровню. Пропуски отмечены, неизвестный путь цены не додумывается.
Открытые сделки в конце отдельно, без принудительного закрытия. PDF показывает
статистику, просадку закрытых сделок и лучшие/худшие/случайные примеры без повторов.
Выборка повторяема (seed 20261110). Нет оптимизации и сравнения запусков.
Ошибка после создания каталога может оставить неполные файлы для диагностики.
Наличие results.json само по себе не подтверждает завершение всей команды;
проверяйте её код выхода.
При ошибке PDF результаты расчёта сохраняются для `--report-only`.

Проверки отчёта и оставшихся утилит данных:

```sh
docker compose run --rm --entrypoint python3 backtest backtest/report/test_render.py
python3 -m unittest discover -s tests
```

## Настройки серверного демона и автономная проверка

Заполните `.env` по именам из `.env.example`; сам пример ключей не содержит.
Не публикуйте `.env`. Готовый бинарник устанавливается на сервер вручную.
Для автономной проверки Linux-бинарника используйте smoke-test в Docker.
Команды `run` и проверки живых подключений выполняются только на сервере.
Автономные тесты ключи не читают.

Команды бинарника:

```sh
./forex-bot check-service .env
./forex-bot smoke-test /tmp/forex-smoke.sqlite strategy/fvg-bot-rules.json
./forex-bot probe .env
./forex-bot run .env
```

`smoke-test` требует новый путь БД и работает без сети. `probe` читает сведения
о боте, группе и котировках настроенных инструментов; сообщения не отправляет
и OpenAI не вызывает.

## Сборка для сервера x86_64 и установка вручную

Сборка не копирует `.env`, базы данных или архивы котировок в образ:

```sh
docker buildx build --platform linux/amd64 --target release --output type=local,dest=dist/linux-amd64 .
docker run --rm --network none --platform linux/amd64 \
  -v "$PWD/dist/linux-amd64:/check:ro" \
  -v "$PWD/strategy/fvg-bot-rules.json:/rules.json:ro" \
  debian:bookworm-slim@sha256:734a72b3d6142a71993b4bc580ca01d8ca687f77a2c422d96a961d3376b179bc \
  /check/forex-bot smoke-test /tmp/forex-smoke.sqlite /rules.json
```

Каталоги установки бинарника, настроек и рабочего состояния выбирает владелец
сервера. Создайте отдельного системного пользователя и настройте systemd unit:
путь к бинарнику и файлу настроек задаётся в ExecStart, рабочий каталог —
в WorkingDirectory. Готовый unit в репозиторий не включён. В примерах ниже
служба называется `forex-bot`; при другом имени замените его в командах.

Создайте в рабочем каталоге подкаталоги `data` и `strategy`, разместите рабочий
JSON по пути STRATEGY_PATH из файла настроек. Относительные пути DATABASE_PATH
и STRATEGY_PATH разрешаются относительно рабочего каталога службы. Каталоги
данных и стратегии должны принадлежать пользователю службы. Файл настроек
с ключами должен быть доступен только администратору и службе (например,
владелец root, группа службы, права 0640).

При обновлении используйте настройки существующей установки. Снимок БД
выполняется только после остановки записывающего её процесса. Исторический
контекст переносится вместе с БД; пустая база требует импорта подготовленной
истории и проверки покрытия.

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now forex-bot
sudo systemctl status forex-bot
sudo journalctl -u forex-bot -f
```

Проверка реального systemd и перезагрузки выполняется пользователем на сервере.
Локальный smoke-test не заменяет проверку группы, изображений, API и живого рынка.

## Эксплуатация на сервере

Локальный рабочий демон не запускается. Локально выполняются бэктесты, сборка
и автономные проверки. Серверная установка и живые интеграции проверяются отдельно.

Демон пишет в stdout статус каждые 5 минут (последняя котировка UTC, ожидающие
планы) и итог поиска сигнала после обработки полной закрытой H4. На сервере
просмотр: `sudo journalctl -u forex-bot -f`. Эти строки не отправляются в группу.

При запуске демон отправляет в группу «Бот запущен» с временем UTC.
При временной недоступности Telegram сообщение остаётся в очереди доставки.

## Локальный комплект обновления

Каталог `deploy/` целиком исключён из Git. Он предназначен для отдельно
подготовленного комплекта обновления: бинарника, рабочего JSON, инструкции
конкретной установки и контрольных сумм. После клонирования этого комплекта нет.
Серверные пути и инструкция конкретной установки не публикуются.

## Рабочий JSON и инструменты

По умолчанию правила читаются из `strategy/fvg-bot-rules.json`; другой путь
задаётся аргументом команды или STRATEGY_PATH в настройках демона. SQLite сохраняет
историю и состояние, но не копию правил. Список `instruments` применяется
после перезапуска. `price_tick` каждой пары задаётся в миллионных долях цены:
В поставляемом example.json: EURUSD=1, GBPUSD=10, USDJPY=1000.
Старый `PRICE_TICK` в .env больше не используется и не обязателен.

`prepare-state <существующая.sqlite> <рабочий.json>` обновляет структуру
существующей базы и подготавливает контекст инструментов без запуска сервиса,
обращений к Telegram/OpenAI и отправки сообщений. Существующая история котировок сохраняется.
Обычные тесты не используют внешнюю сеть.

## Пример структуры SQLite

[data/example.sql](data/example.sql) создаёт пустую SQLite-базу формата v3:
таблицы, ограничения и служебные PRAGMA без котировок, сообщений и состояния.
Пример предназначен для новой базы, не для обновления существующей. Приложение
также умеет создавать схему самостоятельно. История импортируется отдельно.
Рабочие базы и остальные файлы data не публикуются.

Импорт подготовленных минут: `forex-bot import-history <db> <root> [symbol]`.
Без symbol используется EURUSD. Поле source отчёта сохраняет реальное
происхождение данных; пустое название источника отклоняется.
